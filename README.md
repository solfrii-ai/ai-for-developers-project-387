## О проекте

**Календарь звонков** — упрощённый аналог Cal.com для планирования и бронирования встреч.

Владелец создаёт типы встреч с названием, описанием и длительностью, а гости самостоятельно выбирают подходящее время и бронируют встречи. Для обеих ролей регистрация не требуется: страница владельца доступна по заранее определённому адресу.

Сервис показывает только время, которое соответствует расписанию владельца и не занято другими встречами.

## Локальная разработка

Для работы нужен [mise](https://mise.jdx.dev/). Он устанавливает зафиксированные в проекте версии Node.js `24.22.3` и pnpm `12.17.0`. Обязательные переменные окружения не требуются.

Workspace содержит два приложения: React + Vite frontend в `apps/frontend` и Node.js + Express backend в `apps/backend`.

### Установка

```sh
git clone https://github.com/solfrii-ai/ai-for-developers-project-387.git
cd ai-for-developers-project-387
mise install
pnpm install
```

Зависимости обоих приложений устанавливаются из корня pnpm workspace и фиксируются в одном общем `pnpm-lock.yaml`.

### Запуск

```sh
pnpm dev
```

Команда средствами pnpm параллельно запускает frontend и backend. Отдельный пакет-оркестратор не используется.

- Главная страница frontend доступна по адресу `http://localhost:5173/`.
- Backend слушает порт `3000`. Прямая проверка: `http://localhost:3000/api/health`.
- Vite проксирует запросы с префиксом `/api` на `http://localhost:3000`. Frontend вызывает API по относительному адресу `/api` без CORS и без переменных окружения.

### Docker

```sh
docker build -t calendar-calls .
docker run --rm -p 3000:3000 calendar-calls
```

Контейнер стартует автоматически. Порт берётся из `PORT`, по умолчанию `3000`. Страница и `/api/health` доступны на одном порту.

### Production

Сервис `calendar-calls-387` на Render собирает корневой `Dockerfile` и публикует страницу и `/api` по адресу https://calendar-calls-387-zt9y.onrender.com. Пуш в `main` запускает деплой автоматически.

### Проверки

Из корня проекта выполняются проверки обоих приложений:

```sh
pnpm lint
pnpm test
pnpm build
mise run check
```

`pnpm lint`, `pnpm test` и `pnpm build` охватывают frontend и backend. `pnpm build` проверяет TypeScript и создаёт production-сборки в `apps/frontend/dist` и `apps/backend/dist`. `mise run check` проверяет существующие GitHub Actions workflows.

## Роли

### Владелец

Владелец управляет календарём без входа и может:

- просматривать список типов встреч на `/admin`;
- создавать тип встречи с названием, описанием и длительностью;
- открывать публичный список предстоящих встреч.

### Гость

Гость может без регистрации:

- просматривать доступные типы встреч;
- выбирать тип встречи;
- просматривать свободные слоты;
- бронировать встречу, указывая своё имя и почту.

## Правила доступности

- Владелец принимает встречи по будням, с понедельника по пятницу, с 09:00 до 18:00 UTC. Перерыва внутри этих часов нет.
- Выходные дни недоступны. Праздник на буднем дне расписание не закрывает.
- Окно записи — 14 календарных дат UTC, с сегодняшней даты по сегодня+13 включительно. Это не скользящие 14×24 часа.
- Слот предлагается, только если дата его старта входит в это окно и старт не раньше текущего момента.
- Часовой пояс браузера не определяется, ручного выбора пояса нет. Время показывается по UTC без суффикса UTC.
- Шаг возможных начал равен длительности выбранного типа встречи и каждый будний день отсчитывается от 09:00. Общей сетки в 15 минут нет.
- Встреча должна полностью укладываться в рабочие часы: старт не раньше 09:00, конец не позже 18:00.
- Занятые интервалы гостю не показываются. Новая встреча не может пересекаться с уже существующей.

## Основные сценарии

### Создание типа встречи

1. Владелец открывает `/admin`.
2. Если нужного типа нет, владелец создаёт его, указывая название, описание и длительность.
3. Созданный тип становится доступен гостям для бронирования.

### Бронирование встречи

1. Гость открывает список типов встреч и выбирает нужный.
2. Сервис показывает свободные слоты в окне записи с учётом расписания владельца, длительности выбранного типа и существующих бронирований.
3. Гость выбирает подходящий слот.
4. Гость указывает имя и почту и подтверждает бронирование.
5. Встреча появляется в списке предстоящих встреч, а занятое время исключается из доступности для других гостей.

### Просмотр забронированных встреч

Список предстоящих встреч публичный. В нём видны тип встречи, интервал, имя и почта гостя, а также время создания бронирования.

В текущей версии поддерживаются только создание и просмотр встреч. Отмена и перенос бронирований не предусмотрены.
